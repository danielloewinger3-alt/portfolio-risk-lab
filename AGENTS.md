# AGENTS.md: Operating rules for build agents

You are building **Portfolio Risk Lab** overnight with no human available. Optimize for: correct maths, a working deployed-quality app, and a clean git history. Read this file fully, then the docs in the order below.

## Read order

1. `docs/00-decisions.md` (locked decisions: do not relitigate)
2. `docs/01-product-spec.md`
3. `docs/02-tech-stack.md`, `docs/03-architecture.md`, `docs/11-data-spec.md`
4. `docs/04-methodology.md` (formulas are the source of truth for the maths)
5. `docs/05-ml-spec.md`, `docs/06-rag-llm-spec.md`, `docs/08-ui-spec.md`
6. `docs/07-testing-and-validation.md`
7. `docs/09-task-breakdown.md` (your work queue)

## How to work

- Work through `docs/09-task-breakdown.md` **in milestone order**, M0 first. Finish and verify a milestone before starting the next.
- After each milestone: run `make check`, then `git commit` with message `M<n>: <summary>`, then append a dated entry to `docs/PROGRESS.md` (what was built, what was verified, anything surprising).
- If a milestone's acceptance criteria cannot be met, do the closest honest thing, log it in `docs/BLOCKERS.md`, and **move on**. Do not stall the night on one problem. Revisit blocked items at the end.
- If you must deviate from a locked decision or an interface contract, log it in `docs/DEVIATIONS.md` (what, why, impact) and keep the rest of the system consistent.
- Do not start M10 (stretch) until M0 to M9 are complete and green.
- Prefer boring, readable code. No premature abstraction. Type hints everywhere in `src/`.

## Non-negotiables

1. **Never fabricate real data.** No invented prices, returns, filings, or filing text presented as real. Synthetic data is allowed only in tests and must be clearly labeled as synthetic. If the network is unreachable, write the fetch scripts, build against synthetic test fixtures, log a blocker, and tell the human exactly which script to run (`scripts/fetch_sample_data.py`, `scripts/build_index.py`).
2. **The LLM never produces numbers.** All figures in memos and answers come from code outputs via deterministic substitution, and are verified (see `docs/06-rag-llm-spec.md`).
3. **No lookahead.** Every forecasting or estimation routine used out-of-sample must pass a future-perturbation test (see `docs/07-testing-and-validation.md`). Walk-forward validation only; purge overlapping labels.
4. **Formulas follow `docs/04-methodology.md` exactly.** Each finance function has a docstring with the formula, units, sign convention, and assumptions. VaR/ES are reported as **positive loss fractions**.
5. **Determinism.** All randomness takes an explicit `seed` (default 42). Same inputs plus same seed must give identical outputs.
6. **No network in unit tests.** Use fixtures and mocks. Live-network tests are marked `@pytest.mark.network` and skipped by default.
7. **No secrets in git.** Keys live in `.env` (gitignored). Never print keys. Use `.env.example` for documentation only.
8. **Respect data sources.** SEC EDGAR: send `SEC_USER_AGENT` header, max 5 requests/second, cache everything to disk. Yahoo: cache to parquet, be gentle, handle failures with retries and a Stooq fallback.
9. **Honest evaluation.** Report results as they come out, including when simple baselines win. Never tune on the test period. Never claim a number that is not produced by a script in `scripts/` and written to `docs/eval/`.
10. **No investment advice.** The UI footer and memo carry the disclaimer from `docs/08-ui-spec.md`.

## Definition of done (per milestone)

- Acceptance criteria in `docs/09-task-breakdown.md` are met
- `make check` passes (ruff, mypy, pytest)
- New public functions have docstrings and tests
- The app still launches (`make app` smoke test)
- Committed and logged in `PROGRESS.md`

## Definition of done (project)

- All P0 and P1 features in `docs/01-product-spec.md` work in the app with the bundled sample data
- CI green, coverage thresholds from `docs/07-testing-and-validation.md` met
- `docs/VALIDATION.md` generated by `scripts/make_validation_report.py` from real runs
- README contains screenshots and an honest results section
- App deploys on Streamlit Community Cloud from a clean clone using only committed files plus secrets (`docs/10-deployment-and-cv.md`)

## When parallel agents are used

If you are one of several agents, you own only your assigned directories (see "Parallel plan" in `docs/09-task-breakdown.md`). Work in your own git worktree/branch, rebase onto `main` before merging, and never edit another agent's owned files without logging it in `DEVIATIONS.md`.
